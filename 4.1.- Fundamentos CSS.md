# Sesión 1 · Del diseño al código: entorno, estructura semántica y primeros estilos

En la UD1 diseñaste en Figma una app móvil completa: paleta de colores, escala tipográfica, botones, pantallas y prototipo. En esta unidad vas a convertir ese diseño en páginas web reales con HTML y CSS.

Ya trabajaste con HTML y CSS el curso pasado, así que las primeras sesiones son un repaso. Pero no es un repaso sin más: CSS ha cambiado mucho en pocos años, y muchas cosas que antes requerían trucos hoy tienen una propiedad nativa. En este primer tema prepararás el entorno de trabajo, repasarás la estructura semántica de una página y cómo se le aplican estilos, y aprenderás a inspeccionar y validar tu código.

## 1. Objetivos

Al terminar deberías poder:

- Preparar un proyecto web con VS Code, Emmet y Live Server, y revisarlo con el tamaño de un móvil.
- Traducir una pantalla de app móvil a una estructura HTML semántica con `<header>`, `<main>`, `<section>`, `<article>` y `<nav>`.
- Organizar los encabezados con un único `<h1>` y sin saltos de nivel.
- Decidir cuándo usar un enlace (`<a>`) y cuándo un botón (`<button>`), y dar nombre a los botones que solo tienen un icono.
- Identificar las partes de una regla CSS y las tres formas de aplicar estilos, sabiendo que el orden de aparición influye en cuál se aplica.
- Inspeccionar y modificar estilos en vivo con las herramientas de desarrollo del navegador (DevTools).
- Validar el HTML con el servicio del W3C.

> Tailwind no sustituye a CSS: es CSS escrito mediante clases. Cada clase de Tailwind equivale a una o varias propiedades CSS. Si conoces esas propiedades, Tailwind te hará más rápido; si no las conoces, no sabrás arreglar la página cuando algo se descoloque.

### 2.1. El proyecto de la unidad

## 3. Entorno de trabajo

### 3.1. Herramientas

- Visual Studio Code como editor, con Emmet (viene incluido) para escribir HTML más rápido.
- La extensión Live Server, que abre la página en el navegador y la recarga cada vez que guardas.
- Google Chrome o Firefox, con sus herramientas de desarrollo (DevTools).

Hasta el bloque 4.6 no necesitarás instalar Node ni usar la terminal.

### 3.2. Estructura de carpetas

Abre en VS Code una carpeta (File › Open Folder), no un archivo suelto: Live Server necesita una carpeta abierta para funcionar. Para el ejemplo común, crea esta estructura:

```
trastienda-ud4/
├── index.html      pantalla Home
├── carrito.html    pantalla Carrito
├── css/
│   └── estilos.css
└── img/
```

En `index.html`, escribe `!` y pulsa Tab para generar el esqueleto HTML5. Después cambia `lang="en"` por `lang="es"` y escribe un `<title>` descriptivo. Fíjate en esta línea que Emmet añade en el `<head>`:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

Sin ella, el móvil mostraría la página como si fuera de escritorio, reducida y con el texto diminuto. No la borres.

> **No olvides el idioma**
> Sin `lang="es"`, un lector de pantalla leerá tu texto en español con la pronunciación del idioma por defecto (normalmente inglés), y el navegador no podrá ofrecer bien la traducción ni la separación de palabras.

### 3.3. Ver la página con tamaño de móvil

Abre DevTools y activa el modo dispositivo (Cmd + Shift + M en Mac, Ctrl + Shift + M en Windows). En la barra superior, elige un iPhone en Dimensions o escribe 393 × 852, el mismo marco que usaste en Figma. Trabaja siempre con esta vista: lo que se ve bien en un monitor grande no tiene por qué verse bien en un móvil.

### 3.4. Abreviaturas de Emmet útiles

Emmet convierte una abreviatura en HTML al pulsar Tab. El símbolo `>` crea un hijo, `+` un hermano y `*` repite:

```
nav>ul>li*4>a               → barra de navegación con cuatro enlaces
section>h2+article*4>h3+p   → sección con cuatro tarjetas
```

## 4. Leer un diseño como estructura

Antes de escribir CSS hay que leer el diseño como un conjunto de regiones con significado. Es la misma organización que hacías en Figma con capas y frames, pero ahora cada región se marca con la etiqueta HTML que describe su función.

### 4.1. Las regiones de una página (landmarks)

Así se corresponden las partes de la pantalla Home de la app con las etiquetas HTML:

| Elemento | Para qué sirve | En la pantalla Home |
|---|---|---|
| `<header>` | Cabecera de la página o de una sección | Cabecera fija con el nombre de la librería, búsqueda y menú |
| `<main>` | Contenido principal. Solo uno por página | Todo lo que hay entre la cabecera y la barra inferior |
| `<section>` | Agrupa contenido relacionado; normalmente lleva encabezado | El carrusel de Novedades y la lista de Recomendados |
| `<article>` | Contenido que tendría sentido por sí solo | Cada tarjeta de libro |
| `<nav>` | Bloque de enlaces de navegación | La barra inferior (Inicio, Explorar, Cesta, Perfil) y, más adelante, el menú lateral |
| `<div>` | Caja sin significado, solo para agrupar y dar estilo | Un contenedor que haga falta para la maquetación |

Otras regiones habituales en webs, como `<aside>` (contenido complementario) o `<footer>` (pie de página), no aparecen en esta pantalla, pero puede que las necesites cuando amplíes la app a escritorio. Los lectores de pantalla usan todas estas regiones para saltar directamente a la navegación o al contenido principal. Con una página hecha solo de `<div>`, esos atajos no existen.

> **La barra de estado no se maqueta**
> La hora, la cobertura y la batería que dibujaste en Figma las muestra el sistema operativo del móvil, no tu app. En el diseño sirven para que las pantallas sean realistas, pero en HTML no se escriben.

### 4.2. La pantalla Home en HTML

```html
<body>
  <header>
    <a href="index.html">La Trastienda</a>
    <button type="button" aria-label="Buscar">🔍</button>
    <button type="button" aria-label="Abrir menú">☰</button>
  </header>

  <main>
    <h1>Novela negra y thriller</h1>

    <section>
      <h2>Novedades</h2>
      <article>
        <h3><a href="detalle.html">La paciente silenciosa</a></h3>
        <p>Alex Michaelides</p>
        <p>19,90 €</p>
      </article>
      <!-- más tarjetas -->
    </section>

    <section>
      <h2>Recomendados</h2>
      <article>
        <h3><a href="detalle.html">El silencio de la ciudad blanca</a></h3>
        <p>Eva García Sáenz de Urturi</p>
        <p>20,90 €</p>
        <button type="button">Añadir a la cesta</button>
      </article>
      <!-- más tarjetas -->
    </section>
  </main>

  <nav aria-label="Secciones de la app">
    <ul>
      <li><a href="index.html" aria-current="page">Inicio</a></li>
      <li><a href="explorar.html">Explorar</a></li>
      <li><a href="carrito.html">Cesta</a></li>
      <li><a href="perfil.html">Perfil</a></li>
    </ul>
  </nav>
</body>
```

Algunos detalles de este código:

- `aria-label` en el `<nav>` le da un nombre que anuncian los lectores de pantalla. Es útil cuando hay más de una navegación, como ocurrirá cuando añadas el menú lateral.
- `aria-current="page"` indica la pestaña de la pantalla actual. Es el equivalente en código al icono «iluminado» con el color primario de tu diseño, y más adelante lo usarás como selector en CSS para darle ese color.
- Los emojis de los botones son provisionales. Los sustituirás por los iconos SVG exportados de Figma en la sesión 7.

### 4.3. Jerarquía de encabezados

- Un único `<h1>` por página, que resume de qué trata. Si el diseño no tiene un titular visible, el `<h1>` puede ser el nombre de la librería en la cabecera.
- Sin saltos de nivel: después de un `<h2>` puede venir un `<h3>`, pero no un `<h4>`.
- El nivel se elige por la estructura del contenido, no por el tamaño. Tus estilos de Figma text-4xl, text-2xl y text-xl se aplicarán con CSS a los encabezados que correspondan.

### 4.4. ¿Enlace o botón?

La pregunta para decidir es: **¿me lleva a algún sitio o hace algo aquí?**

| | Enlace `<a href="...">` | Botón `<button type="button">` |
|---|---|---|
| Cuándo | Lleva a otra pantalla o a otra parte de la página | Realiza una acción en la pantalla actual |
| En la app | Pestañas de la barra inferior, título de un libro (lleva a su ficha) | Menú hamburguesa, búsqueda, «Añadir a la cesta», mostrar la contraseña |
| Con teclado | Se activa con Intro | Se activa con Intro y con Espacio |

> **Errores habituales**
> Un `<div onclick="...">` no recibe el foco del teclado: quien no usa ratón no puede activarlo. Y un `<a href="#">` usado como botón añade una entrada inútil al historial y hace saltar la página al principio. Compruébalo tú mismo: recorre tu página pulsando Tab y verás qué elementos reciben el foco.

### 4.5. Botones que solo tienen un icono

En una app móvil abundan los botones sin texto: la lupa, la hamburguesa, el [−] y el [+] de la cantidad en el carrito. Un lector de pantalla no puede leer un dibujo, así que estos botones necesitan un nombre con `aria-label` que diga qué hacen:

```html
<button type="button" aria-label="Abrir menú">☰</button>
<button type="button" aria-label="Quitar un ejemplar de La paciente silenciosa">−</button>
```

Sin `aria-label`, el lector anunciaría «botón, menos» o simplemente «botón», sin decir para qué sirve.

## 5. Cómo se añade CSS a una página

### 5.1. Anatomía de una regla

```css
h1 {                  /* selector: a qué elementos se aplica */
  color: #1d4ed8;     /* declaración = propiedad: valor; */
  font-size: 2.25rem;
}                     /* las llaves delimitan el bloque de declaraciones */
```

Cada declaración termina en punto y coma. Si falta uno, el navegador descarta esa declaración y, a menudo, también la siguiente, sin mostrar ningún error.

### 5.2. Las tres formas de aplicar estilos

| Forma | Cómo se escribe | Cuándo usarla |
|---|---|---|
| En línea | `<h1 style="color: crimson;">` | Prácticamente nunca. Mezcla contenido y presentación y no se puede reutilizar. |
| Interna | Un bloque `<style>` dentro del `<head>` | Pruebas rápidas o una página aislada. |
| Externa | `<link rel="stylesheet" href="css/estilos.css">` | Siempre en un proyecto: una sola hoja para todas las pantallas, que el navegador guarda en caché. |

### 5.3. El orden importa

Si una hoja interna y una externa tienen reglas para el mismo selector, gana la que aparece más tarde en el documento:

```html
<head>
  <style>
    h1 { color: darkgreen; }
  </style>
  <link rel="stylesheet" href="css/estilos.css"> <!-- contiene h1 { color: #1d4ed8; } -->
</head>
<!-- El h1 se ve azul: la hoja externa se lee después -->
```

> **Una idea equivocada muy extendida**
> No es cierto que «la hoja interna gana siempre a la externa». Con el mismo selector, decide el orden. Lo que sí gana a ambas es el atributo `style`, y precisamente por eso conviene evitarlo. Las reglas completas (la cascada) se estudian en la sesión 3.

### 5.4. ¿Y `@import`?

Desde una hoja CSS se puede cargar otra con `@import url("otra.css");`. Funciona, pero sin herramientas de compilación obliga al navegador a descargar las hojas una detrás de otra, lo que retrasa la carga. En esta unidad usaremos una sola hoja externa o varios `<link>`.

## 6. Herramientas de desarrollo del navegador (DevTools)

DevTools será tu herramienta principal en esta unidad. Cuando algo no se vea como esperas, no cambies código a ciegas: inspecciona el elemento y mira qué reglas le llegan.

- **Elements:** el árbol HTML tal como lo ha interpretado el navegador. Usa la herramienta de selección (Cmd/Ctrl + Shift + C) para elegir un elemento haciendo clic sobre la página.
- **Styles:** las reglas que se aplican al elemento, con el archivo y la línea de donde vienen. Puedes editar valores y activar o desactivar declaraciones con su casilla. Una declaración tachada es una regla que ha perdido frente a otra.
- **user agent stylesheet:** son los estilos que el navegador aplica por defecto. Por eso un `<h1>` ya es grande y en negrita sin que hayas escrito CSS.
- **Computed:** el valor final de cada propiedad y el diagrama del modelo de caja (margen, borde, relleno y contenido).
- **Console y Network:** muestran los errores de carga, por ejemplo una hoja de estilos que no se encuentra.

> **Mi página aparece sin estilos**
> Casi siempre es una ruta mal escrita en el `href` del `<link>` (por ejemplo, `css/estilo.css` en lugar de `css/estilos.css`). Abre la consola: verás un error 404 con el nombre del archivo que no encuentra. Recuerda también que los cambios hechos en DevTools no se guardan en tus archivos.

## 7. Validar el código

Cuando el HTML tiene errores, cada navegador intenta corregirlos a su manera y el resultado puede variar. Un HTML válido no garantiza una buena página, pero evita muchos problemas difíciles de localizar.

- **HTML:** validator.w3.org. En la pestaña *Validate by Direct Input* puedes pegar tu código, o subir el archivo en *Validate by File Upload*.
- **CSS:** jigsaw.w3.org/css-validator.

> **El validador de CSS va con retraso**
> Las propiedades más recientes a veces aparecen como errores aunque los navegadores ya las admitan. Si te ocurre, comprueba la propiedad en MDN o en Can I Use.

# Sesión 2 · Selectores CSS: de lo básico a `:has()`

En la sesión anterior dejaste lista la estructura de «La Trastienda» y aprendiste a enlazar una hoja de estilos. Hoy nos centramos en la primera pieza de cada regla CSS: el selector, la parte que responde a la pregunta «¿a quién le aplico estos estilos?».

Sin un buen selector, o pintas toda la página de un color, o acabas llenando el HTML de clases que no hacen falta. Empezaremos por lo que ya viste en 1º y llegaremos a selectores modernos como `:is()`, `:where()` y `:has()`.

## 1. Objetivos

Al terminar deberías poder:

- Usar los selectores básicos: universal, de tipo, de clase y de identificador, sabiendo cuándo conviene cada uno.
- Combinar selectores con el espacio, `>`, `+` y `~`.
- Seleccionar por atributo (`aria-current`, `type`, `aria-label`…).
- Aplicar pseudoclases de estado y estructurales: `:hover`, `:focus-visible`, `:nth-child()`, `:not()` y `:empty`.
- Usar `:is()`, `:where()` y `:has()` en casos reales de la app.
- Comprobar un selector en DevTools (panel Styles y consola).

## 2. Anatomía rápida (recordatorio)

```css
nav a[aria-current="page"] {
  color: #2563eb;
  font-weight: 700;
}
/* ↑ selector              ↑ declaraciones */
```

Hoy solo trabajamos el selector. En la sesión 3 veremos qué pasa cuando dos reglas apuntan al mismo elemento y chocan (cascada y especificidad).

## 3. Selectores básicos

| Selector | Ejemplo | Cuándo usarlo |
|---|---|---|
| Universal | `*` | Depurar (por ejemplo, dibujar el borde de todas las cajas). Casi nunca en producción. |
| Tipo / etiqueta | `body`, `h1`, `button` | Estilos base de un tipo de elemento. |
| Clase | `.card`, `.btn-primary` | Componentes reutilizables. Es el selector más habitual en un proyecto. |
| Identificador | `#catalogo` | Anclas y JavaScript. Evita usarlo para estilos si puedes usar una clase. |

```css
body {
  font-family: system-ui, sans-serif;
  color: #1e293b;
  line-height: 1.5;
}

h1, h2, h3 {          /* lista de selectores (OR), no un combinador */
  line-height: 1.2;
}

.card {
  background-color: #ffffff;
  border: 1px solid #e2e8f0;
}
```

> **Clase frente a id**
> Una clase se puede repetir en varias tarjetas o botones. Un id debe ser único en la página. Además, un selector por id gana casi siempre a una clase: mañana verás por qué eso complica el mantenimiento.

Nombra las clases en minúsculas y con guiones: `btn-primary`, `card-title`. Evita espacios y mayúsculas tipo `BtnPrimary`.

## 4. Combinadores

Un combinador relaciona dos selectores según su posición en el árbol HTML. Con la pantalla Home en mente:

```
header
├── a
├── button
└── button
main
└── section
    ├── h2
    └── article.card
        ├── h3 > a
        ├── p
        └── button
nav
└── ul > li > a
```

| Combinador | Sintaxis | Significado | Ejemplo en la app |
|---|---|---|---|
| Descendiente | `A B` | B está dentro de A, a cualquier profundidad | `nav a` |
| Hijo directo | `A > B` | B es hijo inmediato de A | `nav > ul` |
| Hermano adyacente | `A + B` | B es el hermano que va justo después de A | `h2 + .card` |
| Hermano general | `A ~ B` | Todos los hermanos B que van después de A | `h2 ~ .card` |

```css
nav a {
  color: #64748b;
  text-decoration: none;
}

nav > ul {
  list-style: none;
  padding: 0;
}

h2 + .card {
  border-top: 2px solid #2563eb;
}
```

> **El espacio selecciona de más**
> `header a` afecta a cualquier enlace dentro del `<header>`, a cualquier profundidad. No toca la barra inferior (esos enlaces están en el `<nav>`), pero dentro del header puede pillar enlaces que no querías. Para limitar el alcance, usa `>` (hijo directo).

## 5. Selectores de atributo

Permiten apuntar a un elemento por sus atributos HTML, sin inventar clases de más. Encajan muy bien con el HTML semántico y accesible de la sesión 1.

| Selector | Significado |
|---|---|
| `[attr]` | Tiene el atributo, con cualquier valor |
| `[attr="valor"]` | Valor exacto |
| `[attr^="valor"]` | El valor empieza por… |
| `[attr$="valor"]` | El valor termina por… |
| `[attr*="valor"]` | El valor contiene… |

```css
/* Pestaña activa de la barra inferior (sin clase .activo) */
nav a[aria-current="page"] {
  color: #2563eb;
  font-weight: 700;
}

button[type="button"] {
  cursor: pointer;
}

button[aria-label] {
  /* botones de solo icono */
}

a[href^="#"] {
  /* enlaces internos */
}
```

> **Misma marca, dos usos**
> `aria-current="page"` ayuda a los lectores de pantalla y te sirve de selector. Si en `index.html` está en «Inicio» y en `carrito.html` está en «Cesta», el mismo CSS ilumina la pestaña correcta en cada pantalla.

## 6. Pseudoclases de estado y estructurales

Una pseudoclase no elige «otro elemento»: selecciona el mismo elemento en un estado (ratón encima, foco de teclado…) o según su posición / contenido entre hermanos. Se escribe con dos puntos delante del nombre: `:hover`, `:nth-child(2)`, `:empty`…

En este apartado verás tres grupos: estado (`:hover` / `:focus-visible`), posición (`:nth-child()`) y filtro / vacío (`:not()` / `:empty`).

### 6.1. Estado: `:hover` y `:focus-visible`

El foco es el elemento que recibirá la siguiente pulsación de teclado (por ejemplo tras ir con Tab). El hover es cuando el puntero del ratón está encima.

```css
nav a:hover {
  color: #1e293b;
}

nav a:focus-visible {
  outline: 2px solid #2563eb;
  outline-offset: 2px;
}
```

| Pseudoclase | Cuándo se aplica | En la app |
|---|---|---|
| `:hover` | El puntero está encima del elemento | Cambia el color del enlace al pasar el ratón. En móvil apenas se nota (no hay puntero). |
| `:focus` | El elemento tiene el foco, da igual cómo se llegó (teclado o clic) | A veces muestra el anillo también al hacer clic con el ratón, y puede resultar molesto. |
| `:focus-visible` | Tiene el foco y el navegador considera útil mostrar el indicador (sobre todo con teclado) | Al pulsar Tab por la barra inferior verás el anillo; al hacer clic con el ratón, a menudo no. |

**Cómo comprobarlo:** abre la página, pulsa Tab varias veces y observa qué enlace de la barra inferior recibe el contorno. En DevTools, el menú `:hov` del panel Styles permite forzar `:hover` o `:focus` sin usar el teclado.

> **No quites el outline a ciegas**
> `outline: none;` sin una alternativa visible deja la interfaz inaccesible para quien usa teclado. Si lo quitas, sustituye el anillo con un estilo en `:focus-visible`.

### 6.2. Posición: `:nth-child()`

`:nth-child()` responde a la pregunta: ¿qué lugar ocupa este elemento entre los hijos del mismo padre? Cuenta **todos** los hermanos (encabezados, párrafos, artículos…), no solo los que tienen la misma clase.

Imagina esta sección de recomendados:

```html
<section>
  <h2>Recomendados</h2>           <!-- hijo 1 -->
  <article class="card">…</article> <!-- hijo 2 -->
  <article class="card">…</article> <!-- hijo 3 -->
  <article class="card">…</article> <!-- hijo 4 -->
</section>
```

```css
.card:nth-child(odd) {
  background-color: #f8fafc;
}
```

Aquí el primer `.card` es el hijo 2 (par), no el 1: el hijo 1 es el `<h2>`. Por eso a veces el resultado "impar / par" no coincide con lo que intuyes mirando solo las tarjetas.

| Argumento | Significado | Ejemplo |
|---|---|---|
| `2` | Exactamente el hijo número 2 | `.card:nth-child(2)` |
| `odd` | Hijos impares (1, 3, 5…) | Filas alternas |
| `even` | Hijos pares (2, 4, 6…) | Filas alternas |
| `2n` | Cada 2 (igual que `even`) | 2, 4, 6… |
| `2n+1` | Impares (igual que `odd`) | 1, 3, 5… |
| `3n` | Cada 3 | 3, 6, 9… |

También existe `:nth-of-type()`: cuenta solo los hermanos de la misma etiqueta. En el ejemplo anterior, `article:nth-of-type(1)` sería el primer `<article>`, aunque el hijo 1 del padre sea el `<h2>`.

> **Relación con el combinador `+`**
> En el ejercicio usas `h2 + .card` para la primera tarjeta después del título. Eso no es `:nth-child`, pero responde a una pregunta parecida: «el hermano que va justo después». `:nth-child` mira el número de orden; `+` mira el vecino inmediato.

### 6.3. Negación y vacío: `:not()` y `:empty`

#### `:not()` — «todo excepto…»

Selecciona elementos que **no** cumplen el selector que va entre paréntesis. En la barra inferior puedes pintar en gris todos los enlaces salvo la pestaña activa, sin inventar una clase `.activo`:

```css
nav a:not([aria-current="page"]) {
  color: #64748b;
}

nav a[aria-current="page"] {
  color: #2563eb;
  font-weight: 700;
}
```

- Primera regla: enlaces de la barra que no tienen `aria-current="page"` → gris.
- Segunda regla: el que sí lo tiene → color primario y negrita.

Si en `carrito.html` mueves `aria-current` a «Cesta», el mismo CSS ilumina la pestaña correcta sin tocar la hoja de estilos.

#### `:empty` — «sin nada dentro»

Coincide solo si el elemento no tiene hijos ni texto. Sirve para ocultar badges vacíos en las tarjetas de libro:

```html
<span class="badge">Más vendido</span>  <!-- NO está :empty -->
<span class="badge"></span>               <!-- sí está :empty -->
```

```css
.badge:empty {
  display: none;
}
```

| HTML | ¿Coincide con `:empty`? |
|---|---|
| `<span class="badge"></span>` | Sí |
| `<span class="badge">Más vendido</span>` | No |
| `<span class="badge"> </span>` (un espacio) | No: el espacio cuenta como contenido |
| `<span class="badge">\n</span>` (salto de línea) | No: igual que el espacio |

Lo usarás en la práctica 1 para ocultar badges sin texto en la ficha del libro, sin JavaScript.

> **Combinarlas más adelante**
> En el ejercicio de esta sesión también verás `article:has(.badge:not(:empty))`: selecciona las tarjetas que tienen un badge con texto. Ahí se juntan `:has()` (apartado 7), `:not()` y `:empty`.

**Resumen del apartado 6**

- `:hover` / `:focus-visible` → estado (ratón / teclado).
- `:nth-child()` → posición entre hermanos (cuenta todos; `:nth-of-type()` solo la misma etiqueta).
- `:not()` → excluye un caso; `:empty` → sin contenido (cuidado con los espacios).

## 7. Selectores modernos: `:is()`, `:where()` y `:has()`

### 7.1. Agrupar con `:is()` y `:where()`

```css
/* Antes: se repite .card tres veces */
.card h2,
.card h3,
.card p {
  margin: 0;
}

/* Ahora */
.card :is(h2, h3, p) {
  margin: 0;
}

:where(h1, h2, h3) {
  margin-block: 0.5em;
}
```

- `:is()`: agrupa. Su especificidad es la del argumento más específico.
- `:where()`: agrupa igual, pero con especificidad cero, así que es fácil de anular después. Ideal para estilos base o resets.

El cálculo exacto de la especificidad lo verás en la sesión 3. De momento: en componentes suele preferirse `:is()`; en resets, `:where()`.

### 7.2. Seleccionar al padre con `:has()`

Durante años CSS podía seleccionar un hijo, pero no un padre según lo que contenía. `:has()` cierra ese hueco:

```css
/* Tarjetas que tienen un badge con texto */
article:has(.badge:not(:empty)) {
  border-color: #2563eb;
}
```

Está en Baseline de los navegadores actuales. No abuses de cadenas muy profundas (pueden costar más de calcular); para casos como «esta tarjeta tiene badge», es ideal.

## 8. Comprobar selectores en DevTools

- Inspecciona un elemento: en Styles verás qué reglas le llegan y cuáles están tachadas (han perdido).
- En la consola puedes probar un selector sin escribir CSS:
  - `$('nav a')` — el primer elemento que coincide.
  - `$$('article:has(.badge:not(:empty))')` — lista con todos.

## 9. Ejercicio propuesto

Continúa con `trastienda-ud4/` (pantallas Home y Carrito):

1. **Pestaña activa:** escribe una regla para `nav a[aria-current="page"]` (color primario y negrita). Comprueba que en cada HTML se ilumina la pestaña correcta sin cambiar el CSS.
2. **Resto de enlaces de la barra:** `nav a:not([aria-current="page"])` en gris; añade `:hover` y `:focus-visible` con anillo visible.
3. **Tarjetas:** pon la clase `card` a los `<article>` de recomendados. Estiliza la primera de cada sección con `h2 + .card`.
4. **Badges:** en al menos dos libros, un `<span class="badge">…</span>` (uno con texto y otro vacío). Oculta los vacíos con `.badge:empty` y resalta las tarjetas con badge visible usando `article:has(.badge:not(:empty))`.
5. **Botones de icono:** una regla para `button[aria-label]` (el padding fino llega en la sesión del modelo de caja).

## 10. Resumen

- El selector decide quién recibe los estilos. Prefiere clases para componentes; reserva el id para anclas y scripts.
- Combinadores: espacio (descendiente), `>` (hijo), `+` (hermano siguiente), `~` (hermanos posteriores).
- Los atributos semánticos (`aria-current`, `aria-label`) también son selectores.
- `:hover` y `:focus-visible` cubren ratón y teclado; `:empty` oculta badges vacíos.
- `:is()` / `:where()` agrupan; `:has()` selecciona al padre según lo que contiene.

# Sesión 3 · Cascada, especificidad y herencia

En la sesión de selectores aprendiste a apuntar al elemento correcto. Hoy responde a la pregunta que más se repite al maquetar: ¿por qué mi regla no se ve si el selector coincide?

La C de CSS es *Cascading* (en cascada). El navegador no aplica «la última línea que escribiste» a ciegas: sigue un desempate. Cuando lo entiendes, dejas de pelearte con el código a base de `!important`.

## 1. Objetivos

Al terminar deberías poder:

- Explicar los cuatro peldaños de la cascada: origen, capas, especificidad y orden de aparición.
- Calcular la especificidad de un selector y predecir qué regla gana en un conflicto.
- Relacionar `:is()` y `:where()` con ese cálculo.
- Saber qué propiedades se heredan y usar `inherit`, `initial`, `unset` y `revert`.
- Explicar por qué `!important` casi nunca es la solución.
- Organizar estilos con `@layer` y reconocer la idea cuando llegue Tailwind.
- Leer en DevTools qué declaración está tachada y por qué.

## 2. La cascada en cuatro peldaños

Cuando varias reglas afectan a la misma propiedad del mismo elemento, el navegador desempata en este orden. Solo si hay empate se baja al siguiente peldaño:

1. **Origen e importancia** — hoja del autor frente a estilos del navegador; presencia de `!important`.
2. **Capas (`@layer`)** — el orden en que declaraste las capas.
3. **Especificidad** — qué selector apunta «más fuerte».
4. **Orden de aparición** — a igualdad de todo lo anterior, gana la regla que va después en el código.

> **El orden solo decide al final**
> Si una regla tiene más especificidad, gana aunque esté antes en el archivo. «La última gana» solo es cierto cuando origen, capa y especificidad empatan.

En DevTools, el panel Styles muestra las reglas que afectan al elemento. Una declaración tachada es una que ha perdido el desempate.

```css
nav a {
  color: #64748b;
}

nav a {
  color: #2563eb; /* mismo selector: gana esta (va después) */
}
```

Los estilos marcados como *user agent stylesheet* son los del navegador (por eso un `<h1>` ya es grande y en negrita). En condiciones normales, tus estilos de autor ganan a esos.

## 3. Especificidad

La especificidad es un contador de cuatro números. Se compara de izquierda a derecha: el primer valor distinto más alto gana.

| Notación | Qué suma 1 en esa columna |
|---|---|
| (1,0,0,0) | Estilo en línea: `style="…"` |
| (0,1,0,0) | Cada `#id` |
| (0,0,1,0) | Cada `.clase`, `[atributo]` o pseudoclase (`:hover`, `:not()`…) |
| (0,0,0,1) | Cada tipo (`a`, `nav`) o pseudoelemento (`::before`) |

- `*` y `:where()` aportan 0.
- `:is()`, `:has()` y `:not()` aportan la especificidad de su argumento más específico.

### 3.1. Duelos habituales en la app

| Selector A | Selector B | Gana | Por qué |
|---|---|---|---|
| `a` (0,0,0,1) | `.card a` (0,0,1,1) | B | Una clase gana a un tipo |
| `nav a` (0,0,0,2) | `a[aria-current="page"]` (0,0,1,1) | B | Un atributo cuenta como clase |
| `.card` (0,0,1,0) | `#catalogo` (0,1,0,0) | B | Un id aplasta una clase |
| `nav a` (0,0,0,2) | `nav a:hover` (0,0,1,2) | B | La pseudoclase suma en la columna de clases |

> **El id es una apisonadora**
> Si estilas con `#cesta { color: crimson; }`, casi ninguna clase ni atributo podrá cambiar ese color después. Reserva el id para anclas y JavaScript; para estilos usa clases o atributos como `aria-current`.

> **«El más largo gana» es falso**
> `nav ul li a` (0,0,0,4) pierde frente a `.activo` (0,0,1,0). Cuenta la tupla, no el número de palabras.

### 3.2. `:is()` frente a `:where()`

```css
:is(nav, header) a {
  /* cuenta como nav a → (0,0,0,2) */
}

:where(nav, header) a {
  /* :where aporta 0 → solo cuenta a → (0,0,0,1) */
}
```

En componentes suele preferirse `:is()`. En estilos base o resets, `:where()`, porque es fácil de anular después.

## 4. Herencia

Algunas propiedades pasan solas del padre a los hijos. Por eso tiene sentido poner tipografía y color de texto en `body`.

| Suelen heredarse | No se heredan |
|---|---|
| `color`, `font-*`, `line-height`, `letter-spacing`, `text-align`, `visibility` | `margin`, `padding`, `border`, `width`, `background`, `display` |

```css
body {
  font-family: system-ui, sans-serif;
  color: #1e293b;
  line-height: 1.5;
}

header {
  color: #0f172a;
}

header a {
  color: inherit;       /* mismo color que el header, no el azul del navegador */
  text-decoration: none;
}
```

Palabras clave para recuperar o forzar un valor sin inventar uno a mano. Siguen siendo útiles hoy; lo que cambia es cuándo conviene cada una:

| Palabra | Qué hace | Cuándo usarla | En la Trastienda |
|---|---|---|---|
| `inherit` | Copia el valor calculado del padre. | Cuando el navegador no hereda esa propiedad (o la pisa) y quieres el mismo aspecto que el contenedor. | `header a { color: inherit; }` — el logo deja de ser azul «de enlace». |
| `initial` | Valor inicial de la propiedad en la especificación CSS (a menudo «ninguno» o el default: p. ej. `margin: 0`). | Cuando quieres borrar un valor concreto y volver al punto de partida de esa propiedad, sin mirar al padre ni al navegador «con estilos». | `.card h3 { margin: initial; }` — quitas el margen grande del h3 del user agent. |
| `unset` | Si la propiedad es heredable → actúa como `inherit`; si no → como `initial`. | Cuando quieres decir «anula lo que yo había puesto» sin decidir a mano: el CSS elige el camino correcto según el tipo de propiedad. | `.card { color: unset; }` — el color vuelve al del padre; un `margin: unset` en cambio iría a `initial`. |
| `revert` | Vuelve al estilo que aplicaría el navegador (hoja user-agent) o la capa / origen anterior en la cascada. | Cuando un reset o una regla tuya ha ido demasiado lejos y quieres el comportamiento «de fábrica» del elemento (`button`, `ul`…). También encaja con `@layer`. | `button { font: revert; }` — el botón recupera la tipografía típica de control, no la Georgia del body. |

> **Cómo elegir en un segundo**
> ¿Mismo aspecto que el padre? → `inherit`. ¿Quitar mi valor y que CSS decida solo? → `unset`. ¿Volver al default de la propiedad (sin mirar al padre)? → `initial`. ¿Volver a «como el navegador trata este elemento»? → `revert`.

```css
/* Comparación rápida en la app */
header a { color: inherit; }     /* quiero el color del header */
.card h3 { margin: initial; }    /* quito el margen por defecto del h3 */
.card { color: unset; }          /* color heredable → como inherit */
button[aria-label] { font: revert; }  /* tipografía de botón del navegador */
```

En la pestaña Computed de DevTools puedes ver el valor final y, a menudo, de qué regla o herencia proviene.

## 5. `!important`

```css
nav a {
  color: #64748b !important;
}
```

Una declaración con `!important` gana a las normales del mismo origen, incluso a un `#id`. El problema es la espiral: para anularla hace falta otro `!important` más específico, y pronto el archivo se vuelve imposible de mantener.

| ¿Cuándo? | Detalle |
|---|---|
| Casi nunca en tu hoja | Si una regla no gana, baja la especificidad o cambia el orden; no subas la apuesta con `!important`. |
| Sí, con justificación | Anular una librería externa que no controlas, o un caso muy concreto (accesibilidad / impresión) documentado en un comentario. |

> **Norma de la unidad**
> No uses `!important` en las entregas salvo justificación escrita (por ejemplo, anular un estilo de una biblioteca externa que no controlas). Primero revisa si tienes un `#id` de más o un selector demasiado fuerte.

## 6. Capas con `@layer`

Las capas permiten decidir el orden de la cascada **antes** de comparar la especificidad. Una regla en una capa posterior gana a una de una capa anterior, aunque sea menos específica.

```css
@layer base, components, utilities;

@layer base {
  a {
    color: #64748b;
  }
}

@layer components {
  .card a {
    color: #0f172a;
  }
}

@layer utilities {
  .text-primary {
    color: #2563eb;
  }
}
```

Orden de prioridad en este ejemplo: `utilities` > `components` > `base`. Piensa en bandejas: abajo lo genérico, arriba lo concreto.

> **Puente a Tailwind**
> En el bloque 4.6, Tailwind organiza su CSS en capas parecidas (base / Preflight, components, utilities). Por eso una clase utilitaria suele ganar a los estilos base sin que tengas que pelear con tuplas. Hoy solo necesitas la idea.

Detalle: los estilos escritos **fuera** de cualquier `@layer` ganan a los que están dentro de capas.

## 7. Cómo leer el conflicto en DevTools

1. Selecciona el elemento con Cmd/Ctrl + Shift + C.
2. En Styles, localiza la propiedad (por ejemplo `color`).
3. La declaración activa no está tachada; las perdedoras sí. A la derecha verás el archivo y la línea.
4. En Computed confirmas el valor final y si viene por herencia.
5. Con el menú `:hov` puedes forzar `:hover` o `:focus` para inspeccionar esos estados.

## 8. Resumen

- Cascada: origen → capas → especificidad → orden de aparición.
- Especificidad: cuenta ids, clases/atributos/pseudoclases y tipos. El más largo no gana por ser más largo.
- No estiles con `#id`. `:where()` aporta cero; `:is()` toma la del argumento más fuerte.
- Se heredan color y tipografía; no se heredan margen, padding ni fondo. `inherit` alinea enlaces con el texto del padre.
- `!important` es el último recurso. `@layer` ordena base, componentes y utilidades (idea que reaparece en Tailwind).
- DevTools: tachado = ha perdido; Computed = valor final.

# Sesión 4 · Variables CSS, color moderno y anidamiento

- Explicar por qué `oklch()` es perceptualmente uniforme y cómo facilita generar paletas accesibles con gamas amplias de color (P3).

## 2. Custom Properties (Variables CSS)

Hasta hace unos años, cambiar el color corporativo de una web obligaba a buscar y reemplazar el valor hexadecimal en cientos de líneas de código. Las custom properties (conocidas comúnmente como variables CSS) permiten guardar un valor con un nombre descriptivo y reutilizarlo en todo el proyecto.

### 2.1. Declaración y consumo

El nombre de una variable CSS siempre comienza con dos guiones (`--`) y distingue entre mayúsculas y minúsculas (*case-sensitive*). Para utilizar su valor, se llama a la función `var()`:

```css
/* Declaración en el ámbito global (:root) */
:root {
  --color-primary-500: #2563eb;
  --color-primary-600: #1d4ed8;
  --color-text: #0f172a;
  --radius-md: 8px;
}

/* Consumo con var() */
.btn-primary {
  background-color: var(--color-primary-500);
  color: #ffffff;
  border-radius: var(--radius-md);
}

.btn-primary:hover {
  background-color: var(--color-primary-600);
}
```

La función `var()` admite un segundo argumento opcional llamado valor de respaldo (*fallback*). Si la variable no ha sido definida o contiene un valor no válido, el navegador utiliza el respaldo:

```css
.card {
  /* Si --card-bg no existe, usa #ffffff */
  background-color: var(--card-bg, #ffffff);
  border: 1px solid var(--card-border, #e2e8f0);
}
```

### 2.2. Ámbito global frente a ámbito local

El selector `:root` apunta al elemento raíz del documento (la etiqueta `<html>`). Las variables declaradas en `:root` tienen ámbito global: están disponibles en cualquier elemento de la página.

Sin embargo, las variables CSS se someten a la herencia del DOM. Puedes redefinir una variable dentro de una clase o contenedor específico sin tocar el resto de la página:

Un mismo elemento puede tener varias clases separadas por espacio. Es el patrón habitual de componentes con variantes (nomenclatura tipo BEM: bloque + modificador):

```html
<span class="badge">Más vendido</span>
<span class="badge badge--success">Disponible</span>
<span class="badge badge--warning">Últimas unidades</span>
```

```css
:root {
  --badge-bg: #eff6ff;
  --badge-color: #1d4ed8;
}

/* Estilo genérico del componente */
.badge {
  background-color: var(--badge-bg);
  color: var(--badge-color);
  padding: 4px 8px;
  border-radius: 4px;
  font-size: 0.75rem;
  font-weight: 600;
}

/* Variante de éxito: solo redefinimos las variables (ámbito local) */
.badge--success {
  --badge-bg: #ecfdf5;
  --badge-color: #047857;
}

/* Variante de aviso */
.badge--warning {
  --badge-bg: #fffbeb;
  --badge-color: #b45309;
}
```

`.badge` aporta el aspecto y consume las variables. `.badge--success` / `.badge--warning` solo pisan esas variables en ese elemento. Por eso en el HTML van juntas: `class="badge badge--success"`.

> **Variables vivas frente a variables muertas**
> Las variables de SASS (`$color`) se calculaban al compilar y desaparecían en el CSS resultante: eran «estáticas». Las custom properties nativas de CSS están vivas en el navegador: cambian en tiempo real con JavaScript, responden a media queries de modo oscuro (`prefers-color-scheme`) y se heredan por el árbol de etiquetas.

## 3. Formatos de color: del Hexadecimal al espacio `oklch()`

Durante décadas la web utilizó formatos atados al espacio de color sRGB, diseñado en 1996 para monitores de tubo de rayos catódicos (CRT). Las pantallas actuales de móviles y portátiles pueden mostrar colores mucho más intensos y gamas más ricas (Display P3). Para aprovecharlas, CSS incorporó nuevos modelos de color.

| Formato | Sintaxis moderna | Ventajas y limitaciones |
|---|---|---|
| Hexadecimal | `#2563eb`<br>`#2563eb80` (con alfa) | Compacto y universal en herramientas de diseño. Difícil de ajustar a mano sin calculadora y limitado a sRGB. |
| RGB funcional | `rgb(37 99 235)`<br>`rgb(37 99 235 / 0.5)` | Sintaxis moderna sin comas y con barra para la opacidad. Sigue siendo poco intuitivo para crear variantes claras u oscuras. |
| HSL | `hsl(221 83% 53%)`<br>`hsl(221 83% 53% / 0.8)` | Matiz (0-360°), Saturación y Luminosidad. Intuitivo para humanos, pero matemáticamente defectuoso en luminosidad aparente. |
| **OKLCH** (estándar moderno) | `oklch(0.55 0.22 260)`<br>`oklch(0.55 0.22 260 / 0.7)` | Perceptualmente uniforme, compatible con monitores Display P3 y con contraste predecible. El estándar recomendado en 2026. |

### 3.1. ¿Por qué HSL engaña y OKLCH triunfa?

En HSL, tanto el amarillo puro `hsl(60 100% 50%)` como el azul marino `hsl(240 100% 50%)` tienen una luminosidad teórica del 50%. Sin embargo, el ojo humano percibe el amarillo como casi blanco cegador y el azul como muy oscuro. Si pones texto blanco sobre el amarillo en HSL, el contraste falla estrepitosamente.

OKLCH resuelve esto modelando cómo ve realmente el ojo humano:

- **L (Lightness):** luminosidad real percibida (de 0 a 1, o de 0% a 100%). Si dos colores en OKLCH tienen `L: 0.60`, ofrecen exactamente el mismo contraste aparente, sean verdes, azules, rojos o amarillos.
- **C (Chroma):** pureza o saturación del color (desde 0 en escala de grises hasta ~0.37 en tonos vivos).
- **H (Hue):** tono o matiz en el círculo cromático (ángulo de 0 a 360).
- **/ alfa (opcional):** transparencia (de 0 a 1).

```css
:root {
  /* Azul corporativo definido en OKLCH */
  --brand-blue: oklch(0.55 0.22 260);

  /* Para crear un hover más oscuro, solo bajamos la luminosidad L: 0.55 → 0.48 */
  --brand-blue-hover: oklch(0.48 0.22 260);

  /* Para una superficie suave, subimos L al 96% y bajamos el croma C a 0.03 */
  --brand-blue-surface: oklch(0.96 0.03 260);
}
```

> **Conversión al vuelo en DevTools**
> En el panel Styles de DevTools, mantén pulsada la tecla Shift y haz clic sobre el pequeño cuadrado de previsualización del color: irá alternando automáticamente entre Hexadecimal, RGB, HSL y OKLCH.

## 5. Anidamiento nativo en CSS (CSS Nesting)

Históricamente, en CSS estándar había que repetir el selector del padre una y otra vez para aplicar estilos a sus hijos o estados. El anidamiento nativo permite meter unas reglas dentro de otras siguiendo la jerarquía natural del HTML.

### 5.1. Comparativa: código plano frente a código anidado

Observa cómo cambia la maquetación de un componente de tarjeta:

```css
/* ANTES: CSS tradicional plano (repetitivo) */
.card {
  background-color: var(--bg-surface);
  border: 1px solid var(--border-subtle);
  border-radius: 12px;
}
.card:hover {
  border-color: var(--brand);
}
.card .card-title {
  color: var(--text-main);
  font-size: 1.1rem;
}
.card .card-title a {
  text-decoration: none;
  color: inherit;
}
.card .card-price {
  font-weight: 700;
  color: var(--brand);
}
```

```css
/* AHORA: CSS moderno con anidamiento nativo */
.card {
  background-color: var(--bg-surface);
  border: 1px solid var(--border-subtle);
  border-radius: 12px;

  /* & representa al selector padre (.card) */
  &:hover {
    border-color: var(--brand);
  }

  .card-title {
    color: var(--text-main);
    font-size: 1.1rem;

    a {
      text-decoration: none;
      color: inherit;
    }
  }

  .card-price {
    font-weight: 700;
    color: var(--brand);
  }
}
```

### 5.2. El símbolo de referencia al padre: `&`

El carácter `&` (ampersand) sustituye exactamente al selector donde está encerrado. Es obligatorio para conectar estados y pseudoelementos:

- Pseudoclases: `&:hover`, `&:focus-visible`, `&:active`.
- Pseudoelementos: `&::before`, `&::after`.
- Modificadores de clase en el mismo elemento: `&.is-active` (equivale a `.card.is-active`, sin espacio).
- Combinadores directos: `& > p` o simplemente `> p`.

> **Evita el «infierno del anidamiento»**
> El anidamiento es cómodo, pero no anides más de dos o tres niveles de profundidad (por ejemplo `main > section > article > div > ul > li > a`). Un anidamiento descontrolado genera selectores larguísimos, aumenta la especificidad innecesariamente y hace que el CSS sea difícil de sobreescribir y depurar.

## 6. Por qué SASS ya no es necesario en 2026

Durante más de diez años, el preprocesador SASS/SCSS fue una herramienta obligatoria en el desarrollo web. Se utilizaba principalmente por dos aportaciones:

1. Poder definir variables (`$color-primario: #2563eb;`).
2. Poder anidar reglas dentro de otras para organizar componentes.

Hoy, tanto las Custom Properties como el CSS Nesting son estándares oficiales nativos del navegador, soportados por todos los navegadores modernos (Baseline *Widely Available*). No requieren Node.js, no necesitan un paso de compilación que ralentice el flujo de trabajo y tienen la ventaja añadida de que las variables nativas son reactivas en tiempo real. Por eso, en este curso SASS queda formalmente eliminado del temario.

## 2. Unidades de medida en CSS moderno

| Unidad | Tipo | Relativa a | Uso recomendado en la app |
|---|---|---|---|
| `px` | Absoluta | Píxel lógico de pantalla | Bordes finos (`1px`), sombras sutiles. Nunca para fuentes. |
| `rem` | Relativa | Tamaño de fuente de la raíz (`<html>`, por defecto 16 px) | La unidad estándar: tamaños de texto, espaciados (`margin`, `padding`, `gap`) y bordes redondeados. |
| `em` | Relativa | Tamaño de fuente del elemento actual (o de su padre) | Componentes que deben escalar su relleno proporcionalmente al texto (botones, badges). |
| `ch` | Relativa | Anchura del carácter «0» con la fuente actual | Anchura máxima de lectura óptima en párrafos (`max-width: 65ch`). |
| `%` | Relativa | Tamaño de la caja del elemento contenedor | Anchuras fluidas en cajas e imágenes (`width: 100%`). |
| `vw` / `vh` | Relativa | 1% del ancho / alto de la ventana del navegador | Fondos completos y secciones de ancho total. |
| `dvh` | Relativa | Altura dinámica de la pantalla en móviles (*Dynamic Viewport Height*) | Pantallas completas como `01_Login` o menús deslizantes sin desbordar las barras del navegador. |

### 2.1. Por qué no usar `px` para tipografía

Si defines el tamaño de fuente en píxeles (`font-size: 16px;`), ese valor queda grabado en piedra. Si una persona con dificultades visuales configura su navegador o su móvil para que la letra base sea más grande (por ejemplo a 20 px o 24 px), el navegador ignora su preferencia porque el píxel es una unidad absoluta.

En cambio, con `rem` el cálculo se hace multiplicando por el tamaño base del usuario:

```css
/* Si la raíz vale 16 px: */
font-size: 0.75rem;   /* 12 px (Caption / pie de foto) */
font-size: 0.875rem;  /* 14 px (Body Small / autor) */
font-size: 1rem;      /* 16 px (Body base / párrafos) */
font-size: 1.125rem;  /* 18 px (H3 / título de tarjeta) */
font-size: 1.25rem;   /* 20 px (H2 / título de sección) */
font-size: 1.5rem;    /* 24 px (H1 / título de pantalla) */
font-size: 1.875rem;  /* 30 px (Display / portada) */
```

> **El truco prohibido: `html { font-size: 62.5%; }`**
> En tutoriales antiguos verás trucos para forzar que `1rem = 10px` modificando el `font-size` de `html`. No lo hagas: distorsiona las clases de utilidades de Tailwind cuando lleguemos al bloque 4.6 y desajusta las medidas de bibliotecas externas. Acostúmbrate a pensar en múltiplos de 16 px.

### 2.2. `rem` frente a `em`: el efecto acumulativo

En una frase: `rem` = escala **global** (siempre respecto a `html`); `em` = escala **local** (respecto al `font-size` del elemento actual; y si la propiedad es el propio `font-size`, respecto al del padre).

| Unidad | Mira a | Comportamiento |
|---|---|---|
| `rem` | Raíz (`html`) | Predecible a cualquier profundidad. Ideal para tipografía y espaciados globales. |
| `em` | El elemento (o su padre, si defines `font-size`) | Puede acumularse al anidar. Ideal para que el relleno de un componente escale con su texto. |

El efecto «bola de nieve» aparece cuando usas `em` en `font-size` dentro de elementos anidados. Si la raíz vale 16 px y escribes `li { font-size: 0.9em; }`:

```
<ul>                    /* 16 px (hereda de body/html) */
  <li>Nivel 1           /* 0.9 × 16   = 14.4 px */
    <ul>
      <li>Nivel 2       /* 0.9 × 14.4 = 12.96 px */
        <ul>
          <li>Nivel 3    /* 0.9 × 12.96 ≈ 11.7 px  ← cada vez más pequeño */
```

Cada nivel multiplica otra vez por 0.9. Con `li { font-size: 0.9rem; }` no ocurre: en todos los niveles el cálculo es 0.9 × raíz (≈ 14.4 px). Por eso, para tamaños de texto de la página, usa `rem`.

¿Cuándo sí brilla `em`? Para el relleno (`padding`) de componentes, para que acompañe al tamaño de letra de ese mismo componente:

```css
.btn {
  font-size: 1rem;       /* 16 px */
  padding: 0.5em 1em;    /* 0.5×16 y 1×16 → 8 px / 16 px */
}

/* Solo cambia el tamaño de letra; el padding en em se recalcula solo */
.btn--lg {
  font-size: 1.25rem;    /* 20 px → padding pasa a 10 px / 20 px */
}
```

En el HTML el botón grande lleva las dos clases a la vez:

```html
<button class="btn btn--lg">Comprar</button>
```

| Regla | Qué aporta al mismo elemento |
|---|---|
| `.btn` | Estilos base: `font-size: 1rem` y `padding: 0.5em 1em`. |
| `.btn--lg` | Solo sobrescribe el tamaño: `font-size: 1.25rem`. El padding sigue viniendo de `.btn`. |

El navegador combina las reglas del mismo elemento: `.btn--lg` no borra lo de `.btn`; solo sustituye lo que declara. Como el padding está en `em`, se recalcula con el `font-size` final del botón (1.25 rem). No es herencia padre→hijo: es el patrón clase base + modificador sobre el mismo nodo.

> **Si solo pones `class="btn--lg"`**
> El botón tendría el `font-size` grande, pero no el padding de `.btn`. Por eso el HTML correcto es siempre `class="btn btn--lg"`.

> **Regla práctica**
> - Tamaño de texto estable en toda la página → `rem`.
> - Padding o borde de un componente que debe escalar con su texto → `em`.
> - Evita `font-size` en `em` en cadenas anidadas (listas, menús…) para no provocar la bola de nieve.

### 2.3. La unidad `ch` para ergonomía de lectura

En tipografía editorial existe una regla contrastada: las líneas de texto demasiado anchas (más de 75-80 caracteres) cansan la vista porque resulta difícil encontrar el salto a la siguiente línea. Las líneas demasiado cortas (menos de 40 caracteres) rompen el ritmo de lectura con saltos continuos.

La unidad `ch` mide exactamente la anchura del carácter `0` en la tipografía activa. Por tanto, es la unidad perfecta para limitar la anchura de párrafos:

```css
.book-synopsis {
  max-width: 65ch; /* Longitud de lectura ergonómica y cómoda */
  line-height: 1.65;
}
```

### 2.4. El problema de `100vh` en móviles y la solución `dvh`

En teléfonos móviles (Safari en iOS o Chrome en Android), la barra de direcciones superior y la barra de navegación inferior aparecen y desaparecen al hacer scroll. Históricamente, `100vh` medía la pantalla con las barras ocultas, lo que provocaba que los botones fijados al fondo quedaran tapados por la interfaz del propio navegador.

Las nuevas unidades de viewport solucionan este problema de raíz:

- `svh` (*Small Viewport Height*): altura con las barras del navegador desplegadas (espacio mínimo).
- `lvh` (*Large Viewport Height*): altura con las barras del navegador ocultas (espacio máximo).
- `dvh` (*Dynamic Viewport Height*): se adapta dinámicamente y al milímetro a la altura visible real en cada instante.

```css
.login-screen {
  min-height: 100dvh; /* Ocupa la pantalla completa del móvil sin desbordes */
  display: flex;
  flex-direction: column;
  justify-content: space-between;
}
```

## 3. Carga de fuentes: Google Fonts y `@font-face`

Una pila tipográfica (*font stack*) define una lista ordenada de fuentes: si la primera no está disponible o aún se está descargando, el navegador prueba la siguiente hasta llegar a una fuente genérica del sistema operativo:

```css
body {
  font-family: 'Inter', system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
}
```

### 3.1. Carga optimizada con Google Fonts

Para cargar una fuente de Google Fonts sin perjudicar la velocidad de la página, incluye estas etiquetas en el `<head>` de tu HTML:

```html
<!-- Preconexión DNS y TLS anticipada con los servidores de fuentes -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

<!-- Carga de la hoja de estilos con display=swap -->
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700&display=swap" rel="stylesheet">
```

> **El valor clave: `display=swap`**
> Sin `display=swap`, los navegadores ocultan el texto mientras la fuente web se descarga (FOIT: *Flash of Invisible Text*), mostrando una pantalla en blanco. Con `display=swap`, el navegador muestra al instante la fuente del sistema y la sustituye en cuanto la fuente externa esté lista (FOUT: *Flash of Unstyled Text*), lo que garantiza acceso inmediato a la información.

### 3.2. Carga local con `@font-face` y formato `.woff2`

En proyectos profesionales europeos a menudo se exige alojar las fuentes en el propio servidor para cumplir estrictamente con el RGPD (evitando enviar la dirección IP del usuario a Google). Para ello guardamos los archivos en una carpeta `fonts/` en formato `.woff2` (el estándar moderno con compresión Brotli superior) y las declaramos al principio del CSS:

```css
@font-face {
  font-family: 'MiFuenteLocal';
  src: url('../fonts/mifuente-regular.woff2') format('woff2');
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

@font-face {
  font-family: 'MiFuenteLocal';
  src: url('../fonts/mifuente-bold.woff2') format('woff2');
  font-weight: 700;
  font-style: normal;
  font-display: swap;
}
```

## 4. Propiedades tipográficas esenciales

```css
body {
  font-family: var(--font-body, system-ui, sans-serif);
  font-size: 1rem;       /* 16 px base */
  font-weight: 400;      /* Regular */
  line-height: 1.5;      /* ¡Sin unidad! Altura de línea proporcional */
  color: var(--text-main);
}

h1, h2, h3 {
  font-family: var(--font-display, inherit);
  line-height: 1.2;      /* Los titulares grandes necesitan menor interlineado */
  letter-spacing: -0.02em; /* Títulos compactos y elegantes */
  text-wrap: balance;    /* Evita palabras huérfanas en titulares */
}
```

> **Regla de oro: `line-height` SIEMPRE sin unidad**
> Si defines `line-height: 24px;` en `body`, un titular `<h1>` de 32 px heredará esa misma altura de 24 px, y las líneas de texto se montarán unas encima de otras. Si usas un número puro sin unidad como `1.5`, el navegador multiplica cada tamaño de letra por 1.5, adaptando la altura de línea de forma impecable en todos los hijos.

## 5. Criterio profesional: Can I Use y Baseline

En el desarrollo web no basta con que una propiedad funcione en tu ordenador: debes comprobar si funciona en los dispositivos de los usuarios reales. Para tomar decisiones informadas contamos con dos recursos imprescindibles:

### 5.1. Can I Use (caniuse.com)

Proporciona tablas detalladas de soporte por navegador y versión, indicando qué porcentaje de los usuarios globales y de tu país pueden ejecutar esa propiedad sin fallos.

### 5.2. Baseline (MDN y WebDX)

Creado conjuntamente por Google, Apple, Mozilla y Microsoft, Baseline clasifica cada característica web en dos estados claros:

- **Newly available:** la propiedad acaba de ser implementada por los cuatro motores principales (Chromium, Gecko/Firefox y WebKit/Safari). Requiere valorar si tu público objetivo utiliza navegadores antiguos.
- **Widely available:** la propiedad lleva funcionando de forma estable en todos los navegadores principales durante al menos 30 meses. Es segura para producción en el 100% de los proyectos comerciales sin necesidad de parches ni configuraciones especiales.

> **Balance de las novedades del Bloque 4.1**
> Todas las características modernas que has aprendido en estas cinco sesiones (`:has()`, anidamiento nativo de CSS, `oklch()`, `@layer` y las unidades `dvh`) forman parte de Baseline. Puedes utilizarlas con total seguridad profesional.

## 6. Ejercicio propuesto (Cierre del Bloque 4.1)

Completa la hoja de estilos base de tu proyecto personal enlazada con tu pantalla `index.html`:

1. **Carga de fuentes:** Incorpora en el `<head>` las fuentes que elegiste en la práctica de Figma (por ejemplo Inter para cuerpo y Plus Jakarta Sans para titulares) con las etiquetas `preconnect` y `display=swap`.
2. **Variables tipográficas en `:root`:** Añade las variables de fuente y la escala tipográfica:

```css
:root {
  --font-body: 'Inter', system-ui, sans-serif;
  --font-display: 'Plus Jakarta Sans', system-ui, sans-serif;

  --text-xs:   0.75rem;   /* Caption (12 px) */
  --text-sm:   0.875rem;  /* Body Small (14 px) */
  --text-base: 1rem;      /* Body (16 px) */
  --text-lg:   1.125rem;  /* H3 (18 px) */
  --text-xl:   1.25rem;   /* H2 (20 px) */
  --text-2xl:  1.5rem;    /* H1 (24 px) */
  --text-3xl:  1.875rem;  /* Display (30 px) */
}
```

3. **Estilo base del `body`:** Asigna la tipografía principal, `font-size: 1rem`, `line-height: 1.5` y el color neutro oscuro a `body`.
4. **Cero `px` en textos:** Revisa tu CSS y asegúrate de que no queda ningún `font-size` definido con `px`.
5. **Longitud de lectura ergonómica:** Aplica `max-width: 65ch` a los párrafos explicativos de la app.
6. **Altura móvil:** Configura el contenedor principal de tu app para tener una altura mínima de `100dvh`.
7. **Comprobación en DevTools:** Inspecciona un párrafo en el panel Computed y confirma que el navegador ha calculado el tamaño en píxeles esperado respetando la unidad `rem`.
